# 01 · 可行性说明：为什么"自动抓取所有 App 的消费"只能这样做

这份文档解释一件最重要的事：你的需求里哪些能做到、哪些做不到、为什么，以及本项目的取舍。

---

## 1. 一个残酷但必须知道的事实

**安卓系统不允许任何 App 读取其他 App 的私有数据。**

微信的账单存在 `微信私有目录` 里，支付宝存在 `支付宝私有目录` 里。每个 App 运行在独立的 Linux 用户（UID）下，数据目录权限是 `700`，别的 App 连 `ls` 都做不到。

除非手机 **root**，否则不存在"直接读取微信消费记录"这条路。

那鲨鱼记账、随手记这些 App 的"自动记账"是怎么做的？它们走的是下面三条**系统允许**的通道。

---

## 2. 三条合法通道

### 通道一：通知监听（NotificationListenerService）

**原理**：安卓有个官方机制——App 可以申请"通知使用权"，获批后，系统会把**每一条通知的内容**都投递给它。

微信支付成功、支付宝付款、云闪付、招商银行 App 的动账提醒，都会以通知形式出现在状态栏，于是我们能读到：

```
标题：微信支付
内容：你已支付¥25.00
```

**优点**：实时、覆盖广、微信支付宝都在内。
**缺点**：
- 必须用户**手动**在系统设置里授权（App 无法自己申请，这是安卓的设计）
- 通知里必须**带金额**。有些 App 的通知只有"支付成功"，没金额，就抓不到
- 用户关闭了该 App 的通知 → 抓不到
- 部分银行 App 只发"账户变动"不写金额

**能覆盖**：微信支付（约 90%）、支付宝（约 85%）、云闪付、大部分银行 App。

### 通道二：短信读取（BroadcastReceiver）

**原理**：注册 `SMS_RECEIVED` 广播，短信到达时系统会把内容交给你。银行的交易短信模板非常固定：

```
【招商银行】您尾号1234的储蓄卡于11月06日12:30向星巴克支付人民币25.00元，余额1,234.56元。
```

**优点**：几乎 100% 覆盖银行卡消费，包括你没装银行 App 的情况。
**缺点**：
- 需要 `RECEIVE_SMS` 权限（用户要授权）
- 不同银行、不同卡种短信模板上百种，只能靠正则+关键词尽力匹配
- 微信/支付宝**零钱**消费不会发短信（那是通道一负责）

**能覆盖**：储蓄卡、信用卡的直接消费与快捷支付。

### 通道三：账单文件导入

**原理**：支付宝和微信都允许用户导出账单：

- 支付宝：我的 → 账单 → 右上角「…」→ 开具交易流水证明 → 导出 CSV
- 微信：我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 用于个人对账

拿到 CSV 后，App 解析并入库。

**优点**：100% 准确、可以补历史、能覆盖所有漏掉的账。
**缺点**：需要手动操作，不是"自动"。

---

## 3. 为什么不使用"无障碍服务"（AccessibilityService）

你可能会搜到一些教程说：用无障碍服务可以读到屏幕上的一切，甚至能自动点按。

**我们刻意不用**，原因：

1. **隐私风险极大**：无障碍等于把屏幕上所有内容（聊天记录、密码键盘）都暴露给 App，应用商店审核严格禁止
2. **极易失效**：界面一改版就挂，维护成本极高
3. **耗电、卡顿**：持续监听界面变化
4. **容易被系统判定为风险应用**并强制关闭

通知 + 短信已经能覆盖绝大部分场景，够用了。

---

## 4. 那"自动分类"是怎么做的

不是 AI 大模型，是**可解释的规则 + 学习**，又快又准又省电：

```
第一层：用户自定义规则（优先级最高）
        「星巴克」→ 餐饮
第二层：内置关键词词库（200+ 条，最长匹配优先）
        「美团外卖」→ 餐饮
        「手机充值」→ 通讯（比「手机」长，所以优先命中）
第三层：兜底
        支出 → 其他，收入 → 其他收入
```

**学习机制**：当你在明细里把一笔"自动记"的账从「其他」改成「餐饮」，App 会自动生成一条规则「该商户 → 餐饮」，下次直接分对。用得越久越准。

为什么不用本地大模型？—— 手机上跑模型要 2~4GB 内存、耗电、首次加载慢，而记账分类是一个**关键词匹配**问题，规则方案准确率更高、完全可解释、你能随时手改。

## 5. 本项目的能力边界（诚实版）

| 场景 | 能否自动记 | 说明 |
|---|---|---|
| 微信扫码付款 | ✅ | 有通知，含金额 |
| 支付宝扫码付款 | ✅ | 有通知 |
| 淘宝/京东下单付款 | ✅ | 走支付宝/微信，有通知 |
| 银行卡刷卡、快捷支付 | ✅ | 银行短信 |
| 微信零钱转账给个人 | ⚠️ 大多可以 | 通知文案因版本而异 |
| 现金消费 | ❌ | 只能手动 |
| 自动扣费（会员续费） | ⚠️ 部分 | 取决于是否发通知 |
| 别人代付、AA 收款 | ❌ | 需手动 |
| 退款 | ✅ | 识别为收入 |

**实测预期**：日常消费 80%~90% 自动入账，剩下靠「手动记一笔」或「导入账单」补。这已经是安卓的能力上限。

---

## 6. 隐私

- 所有数据存在手机本地 SQLite 数据库（`/data/data/com.beeledger.app/databases/bee.db`）
- App **没有** `INTERNET` 权限（你没看错，AndroidManifest 里没有声明网络权限），物理上不可能上传任何数据
- 通知和短信只在本地做正则匹配，匹配完只存"金额/商户/时间"，原始文本可选保留（用于排错）
- 卸载 App 即删除全部数据

---

## 7. 如果你想要更强的能力

| 需求 | 方案 | 代价 |
|---|---|---|
| 100% 自动、连现金也记 | 做不到 | — |
| 更准的商户识别 | 接入地图 POI / 商户名库 | 需要联网，隐私下降 |
| 语义级分类（"这看起来像请客"） | 调用大模型 API | 要联网、要花钱、隐私风险 |
| 读取微信账单明细 | 只能导出 CSV 导入 | 手动 |
| 后台全自动（root） | 读取其他 App 数据库 | 需 root、保修失效、风险自负 |

如果你以后想做云端同步、多人账本，那就需要后端服务了，那是另一个量级的工程。
